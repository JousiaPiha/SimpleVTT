# Portable Sessions Implementation Plan

> **For agentic workers:** Use subagent-driven-development for isolated storage/UI tasks and native integration; verify the combined change with a fresh reviewer. Track steps below.

**Goal:** Open, copy, close, and clear portable sessions with autosave, a server folder picker, safe switching, and recovery.

**Architecture:** An active session manager owns SQLite/media/import services while Fastify/authentication stay alive. Administrative requests and media URLs carry a runtime generation to reject stale work. Long operations expose progress through polling; the UI resets only after successful switches.

**Tech Stack:** Existing TypeScript, Fastify, SQLite/Drizzle, React, Mantine, Zustand. No new runtime dependency unless necessary for a robust filesystem primitive.

**Spec:** `docs/superpowers/specs/2026-11-05-sessions-design.md`

## Global Constraints

- Save As requires an empty existing destination, copies all indexed assets, changes active folder, and preserves the source.
- Startup chooses Default Session; session transitions and startup leave players blank.
- SESSIONS_ROOT is only an initial picker location and never auto-created.
- Current data/media remain untouched by tests; tests use temporary directories.
- Only authenticated administrators browse folders or mutate sessions; no private data in player payloads.
- Node >=22.13, strict TypeScript, Linux/macOS/Windows paths, self-contained portable files.

## Review Focus

- Same-ID copied sessions and late requests must not share media caches or mutate each other (Task 3).
- Missing/moved storage and default-open failure must not silently create replacement data (Tasks 1, 3).
- Destination races/interrupted copies must preserve unrelated files and never appear complete (Task 1).
- Explicit UI drafts and in-flight imports must block transitions until settled (Tasks 2, 3).
- Open streams/locks must release on close, including a failed return to Default Session (Tasks 1, 3).
